# 评教记录不可删除，删除评教任务不连带作废记录

评教记录曾被设计为"任务删除时一并软删"（为避免记录残留于列表与统计）。但督导删掉自己创建的任务后，其已提交的评教记录随之从列表与统计中消失，而该督导角色并没有「删除评教记录」权限——现象被当作权限绕过上报。实际的权限门是完好的：直删/直改记录的接口都正确拒绝；被漏掉的是任务删除这条旁路，它使 `task:delete_own` 事实上成为删除评教记录的第二种途径，且会连带删掉**他人**提交的记录。对一个把评教结果作为教师评价依据的系统，这意味着排课安排的管理动作能无声抹掉既成的评教事实。

据此确定两条边界。其一，评教记录一经提交不可删除，只能由持有相应权限的角色（`evaluation:delete` / `evaluation:delete_own`）「作废」：作废后记录退出列表与统计口径，但物理数据永久保留、可追溯，同一评教人可对同一任务重新提交；作废需在同一事务内把任务上的评教数、「督导已评」与任务状态回退到与有效记录一致。其二，删除评教任务只软删任务本身（数据保留可恢复），不影响任务名下任何评教记录——记录的存续、可见性与统计口径独立于任务，统计一律只按记录自身的有效状态过滤。这也回到代码里既有的一条立场：记录列表与详情本就不因任务软删而隐藏（对齐旧端）。

被否掉的替代方案：① 维持"任务删除连带作废记录"，仅收紧到 `task:delete` 并加提示——评教事实的存亡仍取决于任务删除权限，长期风险不减；② 禁止删除已有记录的任务——需要新增任务状态与迁移，且误建任务无处安放；③ 让记录携带提交时刻的任务快照——任务编辑即不再影响历史记录展示，但要加列并回填存量，本次收益不抵成本。已知代价：任务元数据（课程名、上课时间、教室）仍可被编辑，历史记录展示会随任务变化；删除任务后其记录不再计入任务维度统计（任务数/已评/待评），但仍计入记录维度统计与同课评教汇总——原先同课汇总与人员统计会排除软删任务下的记录，已一并改为不排除，两套口径各自明确。
