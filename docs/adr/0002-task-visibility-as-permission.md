# 评教任务的可见范围改用权限码 `task:view_all`，默认只给「与我相关」的任务

评教任务曾被当作学院公共数据：接口只要求 `task:view`，再按「被评教师所属学院」过滤，于是普通教师登录后能浏览本学院全体教师的待评清单——包括督导把哪位教师的课排进了待评计划，而这对学校是不合适的。任务的真实性质并非广播数据，而是每位评教人自己的待评课表：因此新增权限码 `task:view_all`（查看他人评教任务），未获授权者只能看到「与我相关的任务」——我创建的、我被评的、我评过的（服务端收敛条件 `relatedToMeCond`）；授权只解除这一层收敛，可见的他人任务仍受学院数据范围（`AccessibleCollegeIDs`）约束，两者是「且」的关系。默认只授予管理员与三类督导（迁移 `015` 幂等补码），`teacher` 不授予——需要放开时由管理员在角色管理页勾选，不必改代码。

有两个决定值得记下。其一，收敛放在服务端查询构造处，而不是保留原有的前端筛选：此前的「我创建的 / 其他创建的 / 全部任务」只是移动端拼的 `create_by` / `create_by_not` 参数，去掉参数即可绕过，等于没有约束。其二，未授权者的集合取三者并集而非仅「我创建的」——评教任务与评教记录同源，评教人既要评自己排的课，也要能看到别人给自己排的课、以及自己已经评过的课；取最小集会把这三条正常路径一并堵死（已与校方确认系统不存在「管理员/督导建好任务、分配给其他老师去评」的流程，故该并集完备）。代价是：教师仍能看到督导给自己建的任务，因此仍会看到任务上的督导相关汇总字段。
